## Local HTTP media validation

`ROSTER_DATA=local node --import tsx scripts/media-smoke.ts` passed against the actual Next.js server at `http://127.0.0.1:3000`. The script and server must share the local data directory and session-secret configuration. It creates disposable fictional accounts and cleans them up.

Nine HTTP status checks passed, alongside assertions for WebP normalization, resizing, EXIF removal, `Cache-Control: private, no-store`, and `X-Content-Type-Options: nosniff`. Invalid-origin and anonymous uploads were denied. Anonymous and non-owner reads of an unattached private upload were denied; authorized active-member access to an attached post image succeeded; deleting the post revoked that access. These checks validate local HTTP handling and authorization, not hosted Storage or manual image cropping.

## Repeatable smoke

`scripts/smoke.mjs` now uses DOB and role onboarding, requires an authenticated matching coach for verification, covers exact post-draft retention plus correction, and exercises private-note persistence and mobile overflow. It stops on the first failed journey and captures a failure screenshot.

`node --check scripts/smoke.mjs` passed. The standalone CLI was not executed in this agent session; browser validation was performed through the required in-app runtime. Therefore the rewritten CLI must be run separately in a local development/CI environment before treating it as validated automation. Use a local-data server only. Generated accounts and content intentionally remain identifiable by the `smoke-` prefix.
